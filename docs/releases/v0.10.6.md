# M5 StopWatch v0.10.6 / Bridge v1.3.5

这是一次针对“按键还正常，但麦克风偶发无声”的音频稳定性更新。

## 用户可感知的变化

- 连续语音输入时，音频流不再一味向已经拥塞的蓝牙队列追加数据。
- 如果发生明确断流，本次 Typeless 听写会停止并提示重新说，避免把缺少中段的语句当作完整输入。
- Bridge 会在后台先重建音频订阅；如果短时间内再次出错，则自动重建 BLE 连接，不再依赖用户手动关闭、重开麦克风。

## 原因与修复

设备每 20ms 发送一包 BLE 音频。当 macOS 或无线环境短暂没有及时消化数据时，旧版固件会在共享 NimBLE 缓冲区紧张时继续快速尝试。这可能让音频包耗尽缓冲，最终出现持续丢包，而低频的键盘事件看起来仍然正常。

v0.10.6 在发送前检查可用缓冲，为 HID、状态和订阅流量留出安全余量。stats 协议同时升级为 v4，Bridge 可以直接看到最后错误、连续失败次数和剩余缓冲，不再只能从“没有声音”反推问题。

Bridge v1.3.5 修正了每次开始录音时固件计数归零的基线判断，并增加两级自动恢复：第一次重建 Audio 通知订阅，60 秒内再次故障时重建整条 BLE 连接。

## 升级与兼容性

- 固件版本：v0.10.6。
- macOS Bridge 版本：v1.3.5。
- 已在 v0.10.x 正常配对的设备不需要在 macOS 中忽略后重新配对。
- 本次没有修改 BLE 音频格式、HID Report Map、分区表、VID/PID 或 bond 结构。
- stats v4 保留前 20 bytes 布局，旧 Bridge 仍可读取基础计数，但建议固件与 Bridge 成对升级。

## 验证

- 公开仓库在 ESP-IDF v5.5.4 下独立全量构建通过，应用镜像为 5,804,848 bytes，应用分区仍有 38% 空间。
- USB `app-flash` 写入和 Flash 哈希校验成功，不改动 NVS 配对信息。
- Bridge v1.3.5 构建、稳定签名安装和启动通过。
- 设备重连后回传 stats v4：空闲状态 `notify_error=0`、`consecutive=0`、`free_mbufs=36`，Core Audio 输出健康。
